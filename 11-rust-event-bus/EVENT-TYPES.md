# Event Types

The nine event classes dispatched by the bus. Each has a stable
`event_id`, a timestamp, and a payload.

## 1. MarketData

```rust
struct MarketData {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    ticker: String,
    bid: Decimal,
    ask: Decimal,
    last: Decimal,
    volume: u64,
}
```

Source: Schwab WebSocket streaming. Subscribers: quote cache, regime
monitor, tail monitor.

## 2. OrderSubmitted

```rust
struct OrderSubmitted {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    order_id: Uuid,
    schwab_order_id: Option<String>,
    ticker: String,
    side: Side,
    quantity: i64,
    limit_price: Decimal,
}
```

Source: execution engine, after Schwab accepts the order.

## 3. OrderFilled

```rust
struct OrderFilled {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    order_id: Uuid,
    ticker: String,
    fill_price: Decimal,
    fill_quantity: i64,
    venue: Option<String>,
}
```

Source: Schwab WebSocket or order status poll.

## 4. OrderCancelled

```rust
struct OrderCancelled {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    order_id: Uuid,
    reason: Option<String>,
}
```

Source: Schwab WebSocket or order status poll.

## 5. LockTransition

```rust
struct LockTransition {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    ticker: String,
    from_state: LockState,
    to_state: LockState,
    trigger_order_id: Option<Uuid>,
}
```

Source: lock monitor, after a buy or sell fills.

## 6. LockExpiry

```rust
struct LockExpiry {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    ticker: String,
    side: Side,  // the side that is now permitted
    lock_expiry_date: NaiveDate,
}
```

Source: lock monitor, scheduled at market open on the expiry date.

## 7. RegimeFlip

```rust
struct RegimeFlip {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    from_regime: Regime,
    to_regime: Regime,
    probabilities: [f64; 3],
}
```

Source: regime detector, after Viterbi state changes.

## 8. FilingEvent

```rust
struct FilingEvent {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    ticker: String,
    form_type: String,
    filing_date: NaiveDate,
}
```

Source: SEC EDGAR poll, after a new filing is detected.

## 9. AuditEvent

```rust
struct AuditEvent {
    event_id: Uuid,
    timestamp: DateTime<Utc>,
    event_type: String,
    ticker: Option<String>,
    actor: String,
    details: serde_json::Value,
    severity: Severity,
}
```

Source: every handler, as the last step before return. Subscriber: audit
writer.

## 10. Event ID Rules

- Every event has a unique `event_id` (UUID v4).
- The `event_id` is generated by the producer, not the bus.
- The `event_id` is the idempotency key.
- Handlers do not modify `event_id`.
- The audit writer preserves the `event_id` in the audit record.

## 11. What Not to Do

- Do not reuse an `event_id` across events. It is the idempotency key.
- Do not generate `event_id` in the handler. The producer owns it.
- Do not omit `timestamp`. Every event has one.
- Do not add a field to an event without updating this file and the
  audit writer's schema mapping.
